# 個人開発AI依頼文工房

**「作りたい」を、AIに伝わる依頼文へ。**

プログラミングの知識がなくても、いくつかの質問に答えるだけで、ChatGPT・Claude・Codex・Claude Code に渡せる「開発の依頼文」を作る静的Webツールです。

- 工房自身はAIを呼び出しません。アイデアもコードも作りません。作るのは「AIへの依頼文」だけです。
- 登録・ログイン・APIキー・課金は不要です。
- 入力内容は外部へ送信しません。保存はこの端末のブラウザ（localStorage）の中だけで、オフにできます。
- アクセス解析・広告・外部CDN・外部フォントは使っていません（CSPで `connect-src 'none'`）。

## 3つの入口

| 入口 | 対象 | 依頼文の中身 |
|---|---|---|
| ① アイデアを考えたい | 何か作りたいが具体案がない | 複数案の提案、魅力・主要機能・難易度の比較、GitHub Pagesだけで作れるかの区別、簡易版、②へ引き継ぐ要約形式 |
| ② 新しく作りたい | 作りたいものが決まっている | 目的・利用者・必須／任意機能・今回やらないこと・保存・公開・完成条件・実現方法の前提・未確定事項 |
| ③ 作ったものを直したい | 機能追加・変更・デザイン・不具合・公開 | 依頼内容（Before/After、再現手順・期待結果・実際の結果）、**変更してはいけないこと**、元に戻す準備、確認・報告 |

①で選んだアイデアは、②の最初の欄に貼り付けて引き継げます（コピー＆ペースト方式）。

### 出力の切り替え

- **出力先**：共通／ChatGPT／Claude／Codex／Claude Code
  - ChatGPT・Claude（チャット向け）：設計相談、コードの全体提示、初心者向けの確認手順
  - Codex・Claude Code（エージェント向け）：作業ルールファイル（AGENTS.md / CLAUDE.md）の確認、計画→最小変更→テスト→差分確認→報告
  - ChatGPT向けとClaude向けは同じ組み立てです（AIごとの最適化を装わないため。画面にも明記）
- **依頼の段階**（②③）：相談・設計用／実装・改修用。②の既定は相談、③は実装（公開の相談だけ相談）

### 画面だけに出るもの（コピーされない）

- GitHub Pages適性（②）：「静的Webアプリとして実現しやすい」「外部サービスとの連携が必要」「追加の技術的検討が必要」＋判断に必要な情報の不足
- 注意事項：秘密情報・個人情報らしき文字列、未確定項目、保存（バックアップ）の勧め、「依頼文だけで破損は完全に防げない」旨
- 自分で確認するチェックリスト、入力のまとめ（各ステップへ戻って修正）

## 指示書からの判断・変更点

- **質問数を抑えるため**、任意の詳しい質問は「もっと詳しく伝える（任意）」に折りたたみ、条件で不要な質問は出しません（例：共有を選んだときだけ共有先、端末保存のときだけバックアップ、③は目的ごとに2ステップ目が入れ替わる）。
- **秘密情報**：APIキー・トークン・パスワードらしき文字列は、依頼文・自動保存・JSON書き出しで伏せ字にします（パターン検出なので見逃しはありえます）。
- **入力の保持**：自動保存は既定でオン（オフにすると保存データを消去）。JSONの書き出し・読み込みは型・選択肢・文字数を検証します。
- **改修依頼**：どの目的・出力先・段階でも「変更してはいけないこと（最重要）」「必要最小限の変更」「元に戻せるようにすること」を必ず入れます。
- 後回しにしたもの：AI APIの組み込み、ユーザー登録、クラウド保存、GitHubリポジトリの自動解析、自動コード生成。

## 構成

```
index.html                  画面（CSPで外部通信を禁止）
assets/styles.css           スタイル（外部フォントなし）
src/app.js                  画面の組み立て・ルーティング（#/、#/create/2、#/create/result、#/about、#/glossary）
src/data/modes.js           3つの入口のフォーム定義（ステップ・項目・表示条件・必須条件）
src/data/options.js         共通の選択肢、出力先・段階の一覧
src/data/targets.js         出力先ごとの文言（製品名や機能に関わる文言はここに集約）
src/data/examples.js        入力例プリセット
src/data/glossary.js        用語集
src/logic/form.js           初期値・表示条件・検証・整形（DOM非依存）
src/logic/feasibility.js    GitHub Pages適性の判定ルール
src/logic/secrets.js        秘密情報・個人情報らしき文字列の検出と伏せ字
src/logic/persist.js        localStorage保存、JSONの書き出し・読み込みと検証
src/prompts/build.js        依頼文生成の入口（＋注意事項・チェックリスト・まとめ）
src/prompts/idea.js / create.js / fix.js   入口ごとのテンプレート
src/prompts/common.js, md.js               共通の文・Markdown組み立て
src/ui/                     DOM補助（innerHTML不使用）、フォーム部品、コピー、ダウンロード
tests/unit/                 Node標準のテスト（node:test）＋依頼文スナップショット
tests/e2e/run-e2e.mjs       Playwrightによるブラウザ操作テスト（iPhone 13相当／320px／PC幅）
```

ビルド不要の ES Modules 構成です。

- 質問を足す：`src/data/modes.js` に項目を追加し、`src/prompts/` の該当テンプレートで使う
- 出力先を足す：`src/data/options.js` の `TARGETS` と `src/data/targets.js` に追加
- 判定ルールを足す：`src/logic/feasibility.js`

## 動かし方

ES Modules を使うため、`file://` で直接開くと動きません。ローカルでは簡易サーバーで開きます。

```sh
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

## テスト

```sh
npm test                          # ユニットテスト（依存なし）
npm i                             # 初回のみ（Playwright）
npm run test:e2e                  # ブラウザ操作テスト（スクリーンショットは test-results/）
node tests/update-fixtures.mjs    # 依頼文の文言を意図して変えたときだけ、スナップショットを更新
```

## GitHub Pages で公開する

1. このリポジトリを GitHub に push する
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にする
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

`.nojekyll` を置いているので、Jekyll の処理は行われません。

## 注意

- GitHub Pages適性は、回答から機械的に判定した参考情報です。外部サービスを組み合わせれば実現できる場合もあるため、「可能／不可能」とは断定しません。
- 依頼文で「変更しないこと」を伝えても、AIが既存機能を壊さないことは保証できません。
- 秘密情報・個人情報の検出は簡単なパターンによるもので、表示されなくても含まれていないとは限りません。
- AIの製品名・機能は変わりやすいため、製品固有の文言は `src/data/targets.js` にまとめ、「使える場合は」という条件つきで書いています。
